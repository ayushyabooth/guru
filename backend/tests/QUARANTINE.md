# Quarantined backend tests

A quarantined test can't pass today. It carries `@pytest.mark.quarantine(reason="...")`, so `make test`, `make test-legacy` and CI skip it, and `make test-quarantine` runs only these (they fail until fixed). Nothing was deleted. Each one is listed here with its root cause and what would fix it, and a fix removes the marker and the row in the same commit. A marker without a reason stops the run.

36 tests in 7 files, as of GUR-253 (10/7). The other 217 legacy tests pass, in CI too. Every test runs behind `tests/conftest.py`: no network, no embedding model download, stand-in secrets, and the tables created in the throwaway database.

| Test | Root cause | What would fix it |
|---|---|---|
| `test_auth_simple.py::test_password_edge_cases` | A real bug. bcrypt 5 raises on a password over 72 bytes and `hash_password` passes it through, so a password of 73 to 128 bytes (the signup schema allows 128 characters) fails signup with a 500. | Cut or reject passwords over 72 bytes before bcrypt sees them, in `hash_password` and `verify_password`, or cap the schema at 72 bytes. An app change; this test then passes as written. |
| `test_catchup_performance.py`, all 4 | A benchmark for a populated database, not a unit test. It needs real storyboards (articles and the embedding model, a download), times requests against wall-clock limits a shared CI runner can't promise, reuses one email address, and imports `app.utils.auth`, which no longer exists. | Move it to a script run by hand against a seeded local database, or rewrite it on seeded fixtures and a fake embedding model, without timing asserts. |
| `test_metrics.py`: `test_get_metrics_summary`, `test_metrics_update_after_logging`, `test_metrics_streak_calculation`, `test_metrics_week_history` | `/me/metrics` counts the user's local day with Postgres's `timezone()`, which SQLite doesn't have. | Run them against Postgres (a service container in CI), or make the day math work on both databases. |
| `test_models.py::test_recap_session_flow` | It builds `RecapQuestion` and `RecapResponse`, models that no longer exist: recap moved to `RecapJourney`. | Rewrite it against `RecapJourney`, or delete it (the owner's call). |
| `test_recap_api.py`: `TestRecapEndpoints::test_answer_recap_question_endpoint`, `test_answer_recap_question_validation`, `test_publish_recap_endpoint`, `test_view_shared_recap_endpoint`, and `TestRecapIntegration::test_complete_recap_workflow` | Written for the RecapSession API. `/recap/start` now starts a journey, `/recap/{id}/answer` takes a journey answer (422), and publishing is gone (404). | Rewrite them against the journey routes, or against `/recap/start-session` and `/recap/{id}/legacy-answer` while the legacy flow lives. |
| `test_save_article_divein_flow.py`: 5 of the 6 in `TestSaveArticleDiveInFlow`, all but `test_save_article_from_catchup` | Written for the old dive-in feed: one `articles` list, for a user with no profile. The feed now answers 404 without a profile and returns `saved_articles`, `essential_articles` and `discovery_articles`. | Give the test user a profile and read the three sections, as `test_divein_feed.py` does. |
| `test_storyboard_feed.py`, all 16 | Never ran. It asks for a `client` fixture that was never written, uses mocks it never defines (`mock_get_db`, `mock_generate_prompt`), and patches `get_db`, which each route's `Depends` captured at import, so the patch couldn't take effect anyway. | Rewrite it on `httpx.ASGITransport` with `app.dependency_overrides`, as the gate files do, or delete it: `test_storyboards.py` covers the same routes. |
