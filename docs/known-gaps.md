# Known gaps

What is wrong or unfinished in Guru today, written down so nobody discovers it twice. Some gaps are pinned by a test on purpose: the test changes when the gap is fixed, so a fix is a visible decision, not an accident. An eval pin is a case in `backend/evals/cases.yaml` that is red today; its label and `fix` say what turns it green. A fix updates this file in the same commit.

## The agent

| Gap | What happens | Pinned by |
|---|---|---|
| The iteration cap ends a turn silently | After `MAX_ITERS` model calls in one turn, the turn stops with no final answer and no message to the user. Only what streamed before the cap stays on screen. The trace records outcome `max_iters`. | `test_a_runaway_tool_loop_stops_at_max_iters`, `test_the_iteration_cap_is_traced`, eval ERR-05 |
| A cut-off answer looks finished | The loop only checks for `stop_reason == "tool_use"`. An answer cut off at `max_tokens` is parsed like a finished one, so the user can get a partial turn with no notice; the admin view flags it. A cut inside a tool call saves a `tool_use` with no `tool_result`, and the next turn sends that broken history to the API (seen with a scripted model; no test yet). | eval MAL-03 |
| A tool that raises ends the whole turn | Only HTTP errors go back to the model. A missing required argument (a `KeyError` in `_execute_tool`) or an unhandled exception in the route ends the turn with an `error` event, so the model never gets to adapt. The live model does call writes with no arguments. | `test_a_raising_tool_is_named_in_the_trace`, eval ERR-03 |
| Raw exception text reaches the screen | The `error` event carries the exception message, and the app shows it after "Something went wrong". A `KeyError` shows a bare field name. | `test_a_model_error_becomes_an_error_event_and_rolls_back`, eval ERR-03 |
| A malformed answer shows raw model output | When the final text doesn't parse as blocks, `_parse_blocks` returns the whole output as one text block. If no block streamed first, the user sees that raw text, JSON and all; if some did, whatever didn't parse is dropped without notice. | `test_parse_blocks_falls_back_to_one_text_block_on_malformed_json` |
| `approval_id` is recorded, not enforced | A decision runs whatever write is pending, whatever card id it carries; a mismatch is only recorded in the trace (`approval_matched`), and the admin view reports a stale tap even when the write ran. A decision with nothing pending still runs a model turn. An approval card stays tappable after the user types past it, though the server has already treated that write as declined. | evals APR-06, APR-07 |
| An approved write can stay pending after a failed turn | When an approved note or commitment is written and the model call after it fails, the turn rolls back but the write stays. The session still holds it as pending, the card already shows "Approved", and the user's next message makes the server tell the model it was declined; the admin view then says the write was dropped (seen with a scripted model; no test yet). | - |
| A failed approved write is reported as executed | When an approved note or commitment comes back with an HTTP error, the model is told "User APPROVED. Executed:" followed by the error. The admin view flags it. | - |
| Unknown block types reach the app | The server forwards any block that has a `type`. The app drops unknown types silently. The trace records every block's type, but no rule flags an unknown one. | eval MAL-05 |
| The model can draw its own approval card | Approval cards are a server-only type, but the server forwards one the model writes, and the app draws it like a real card. Tapping Approve on it runs whatever write is pending, since a decision isn't bound to its card. A `user_echo` the model writes shows up as the user's own words. | eval MAL-06 |
| Immediate writes have no server-side check | `save_article`, `save_highlight` and `mark_not_relevant` run the moment the model calls them (the tap is the consent). Only a prompt sentence stops an unasked write, and article text is untrusted input: in live runs, an instruction planted in an article sometimes got `save_article` called. | evals INJ-04 (STAY RED 1), INJ-01 |
| The crux protocol asks for saved highlights | The prompt's goal ("by the end of a crux the user has saved 1-2 highlights") pulls against `save_highlight`'s "never unprompted", so in a walkthrough the agent sometimes highlights a line nobody asked it to keep, with or without a planted instruction. | evals INJ-01C, INJ-01 |
| A turn can end without pills | Only the prompt asks for closing pills; the server never adds them. Refusals miss them most: the agent refuses "Delete all my notes" correctly, but some runs end on a text or a quote with no next move. | eval PLAN-07 |
| Dive-in reflection questions arrive empty | `_slim_tool_result` reads `socratic_prompts` at the top level of each saved article, but the dive-in feed nests them inside `rich_summary`, so the agent never gets them. | - |
| Dive-in is slow to first content | Catch-up shows a headline strip the server draws as soon as the feed returns; dive-in has nothing like it, so "Dive into my saved queue" waits on its biggest tool result and the model. In live runs its first block took 5.4 to 9.5 seconds against a 4-second budget, on frozen tool data; production adds the feed's own time. | eval PERF-03 (STAY RED 2) |
| Only the prompt prefix is cached | The one cache breakpoint is on the static system block, so everything after it, the whole conversation and its tool results, is sent at full input price on every model call. | - |
| Thinking is dropped between model calls | Sonnet 5 thinks by default, but `_serialize_content` keeps only text and tool calls, so after each tool result the model goes on without the reasoning that picked the tool. The API accepts this, so nothing errors. | - |
| The agent's "today" is UTC | `get_metrics` sends no timezone, so the agent's rings and "notes today" count the UTC day, while Home counts the user's local day. | - |
| The agent's context holds the raw commitment object | The second system block prints the whole `/me/commitment` object, week dates and journey id included, where only the commitment's text belongs. | - |
| A FastAPI background task holds the response open | `main.py`'s timing middleware ends a response only after its background tasks finish, so work handed to `BackgroundTasks` makes the user wait. The recap commitment's audio warm-up does this today, including when the agent sets a commitment. Report a bug avoids it with its own thread pool. | - |
| Cold-open mini cards never show an image | The headline strip the server streams after `get_catchup_feed` shows the placeholder square on every card. | eval UI-11 |
| Skip hides the story | The agent calls `mark_not_relevant` on a skip, which hides the story from the catch-up feed under one filter (`core` unless the model passes another). On "next" it sometimes does the same, hiding the story the user just read. Whether Skip should hide a story or only move on is an open product decision; "next" should never hide one. | eval STEP-07 |
| The Interrupt box can't interrupt | While a turn runs, the input says "Interrupt or redirect…", but Send is disabled, and Enter or a pill clears the typed text and sends nothing. | - |
| Save and remove show "working…" | `STATUS_TEXT` has no line for `save_article` or `mark_not_relevant`, so while one runs the user sees the generic "working…". | - |
| Stale approval-card wording | The `save_article` and `mark_not_relevant` tool descriptions still say their title is "shown on the approval card", though neither has had a card since saves and removals stopped being gated, and `_approval_block` keeps their dead branches. | - |
| Some block colors break the color vocabulary | Blue, pink and orange mean catch-up, dive-in and recap in the agent UI, but in every mode the quote block is recap orange, the "why it matters" dot is dive-in pink, and the big stat and the Read buttons are catch-up blue (`BlockRenderer.tsx`). | - |
| A failed turn drops its writes from the agent's memory | When a turn fails after an immediate save or highlight ran, the write stays, but the turn is left out of the saved conversation, so on the next turn the agent doesn't know it saved anything. | - |
| An approval card can say Approved when the decision failed | If the decision request comes back with an HTTP 500, the card still shows "Approved". | - |
| The highlight icon draws as a circle | `Icon.tsx` maps `marker` to Phosphor's `Marker`, which phosphor-react-native 3.0.4 doesn't export, so the reader's highlight buttons fall back to a plain circle. | - |
| Repaired JSON goes unrecorded | In the 10/7 live eval run, about one answer in five needed the stream parser to repair its block JSON. The eval check K1 tallies it; production records no repair, so its rate there is unknown. | eval check K1 (tallied, not gated) |
| Hard text slices | Some text in `agent.py` is cut with `text[:n]`: tool results in `_slim_tool_result` (the deep-read excerpt at 2,400 characters, for one), the session title and the error text. Two of the slices cut serialized JSON, which can hand the model broken JSON. | - |
| `docs/agentic-ui-architecture.md` has drifted | It says 10 tools, every write gated, strict structured outputs, `claude-sonnet-4-6`, `max_tokens` 2048 and an `AGENT_MAX_ITERS` setting. The code has 18 tools, two gated writes, a tolerant block parser, `AGENT_MODEL` (`claude-sonnet-5` by default), 4096 and a `MAX_ITERS` constant. | - |

## Tests and checks

| Gap | What happens | Pinned by |
|---|---|---|
| The legacy backend suite runs no tests | `make test` stops during collection, before any test runs: three files import modules that no longer exist. Past that, the TestClient tests break on the installed httpx. Collection alone creates missing tables and columns in the database `DATABASE_URL` names (locally, `backend/test.db`), and the tests, once they run, create users there. | - |
| The app type check can't give a signal | `npx tsc --noEmit` in `mobile/` stops on syntax errors in `__tests__/e2e/complete-auth-flow.test.ts`, and while any syntax error exists tsc reports no type errors at all. With that file excluded, it reports type errors in app code too. | - |
| Nothing runs on a push | There is no CI. `make test-agent` runs by hand, or from a local Claude Code hook after an edit to the agent, and the evals run only by hand. | - |
| The T1 evals can't see the database or the HTTP layer | T1 drives the real route, but on the contract tests' fake database, whose rollback undoes nothing, and by calling the route function directly, so auth, request validation, exception handlers and disconnects never run. No eval can catch a gap that lives there, like an approved write left pending after a failed turn. | - |
| The LLM judge is not calibrated | On a live run Claude Opus 5.5 grades each judged case, but it stays report-only until at least 20 owner labels agree with it 85% of the time and the owner switches it on. `calibration.yaml` has no labels yet, so its verdicts have never been checked against a person's. | - |

## Report a bug (beta)

| Gap | What happens | Pinned by |
|---|---|---|
| A report carries one turn | The Linear issue and Claude's triage see only the reported turn (what the user typed, its tools and blocks, the rule findings), not the turns before it. | - |
| A deploy can strand a report | Filing and triage run in a thread pool inside the server, and every deploy restarts it. A report caught mid-filing stays "saved" until an admin retries it. | - |
